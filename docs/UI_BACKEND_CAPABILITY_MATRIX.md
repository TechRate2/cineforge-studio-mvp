## Missing UI Contract Notes

- `/studio` receives polled job data through `JobResultModal.onJobUpdate`. The chat-first timeline uses `render_execution`, `longform_render_execution`, `assembly_result`, and output URL fields when present. It must still show pending/unknown when those fields are absent.
- `/studio/history` and Recent Generations sanitize persisted `output_url` fields before preview. Only `http`/`https` delivery URLs are previewable; `file://` and local paths remain non-deliverable metadata.
- Benchmark evidence is fetched from the job evidence-pack endpoint only after a job reaches `done`. A missing or failing evidence-pack response leaves the benchmark step pending. A returned draft pack is not treated as benchmark success unless `evidence_validation_preview.promotion_ready` is true; unsafe feedback integrity adds `feedback_integrity_not_safe` to `missing_reasons`, and the main timeline translates that blocker into readable launch-evidence copy.
- Reference Intelligence is available only after dry-run because the current report is generated by `RenderDryRunService`. Before dry-run, UI can show local role confirmation and upload readiness, but must not claim backend Reference Intelligence has passed.
- Reference Intelligence V1 is metadata-based only. The UI must not claim image, logo, face, product, video, or audio understanding unless a future analyzer provides computed evidence.
- Normal Studio dry-run/render keeps `use_vision_llm_for_tagging=false`. `Phân tích sâu / Deep analyze` may opt into vision suggestions, but those suggestions are advisory role hints, not production proof of visual/audio understanding.
